# Как работать вместе

## Первый запуск разработки

Каркас не содержит запущенного сервиса: команды запуска приложения пока нет.

```bash
git clone https://github.com/Masha831/Agentic_Systems_HSE.git
cd Agentic_Systems_HSE
python3 -m venv .venv
source .venv/bin/activate
cp .env.example .env
```

Windows PowerShell: вместо `source` используйте `.venv\Scripts\Activate.ps1`, вместо `cp` — `Copy-Item .env.example .env`.

Предлагаемый минимум — Python 3.11+. Первый PR с рабочим сервером должен добавить `pyproject.toml` или `requirements.txt`, команду установки и запуска. Сейчас внешних зависимостей нет. Значения `.env` читаются только кодом сервера после реализации настройки; само копирование файла их не загружает.

## Ветки

Первый организационный каркас опубликован в `main` по запросу команды. Следующие изменения делаем в отдельных ветках и объединяем через pull request.

```bash
git switch main
git pull --ff-only
git switch -c feature/liza-voice
```

Примеры других веток: `feature/masha-interviewer`, `feature/maxim-archive`, `feature/daria-editor`. Для новой задачи создавайте новую ветку. Не используйте force push в общей ветке.

В PR: что сделано, как запустить и проверить, что пока не реализовано, какие общие поля или функции изменились. При изменении контракта обновить `docs/CONTRACTS.md` и пример, согласовать с участниками, которые вызывают эту функцию. Назначение ответственного в README не настраивает права GitHub и не запрещает помощь друг другу.

## Общие файлы

- `backend/main.py` и серверная конфигурация: первоначальная сборка — Лиза, изменения согласуются с владельцами маршрутов.
- `backend/shared/`: модели и доступ к истории — Максим, формат согласуют все потребители.
- `frontend/index.html`, общие стили и существующий `app.js`: UI Маши — основа; Лиза и Дарья договариваются о подключении своих частей. Не редактировать большой общий файл одновременно без согласования.
- Общий перечень зависимостей: добавлять только используемые библиотеки, объяснять назначение.

## Данные

Ключи только в локальном `.env` или настройках сервера. В GitHub не загружать реальные семейные фото, записи, расшифровки, базы и персональные данные. Для проверок — `examples/demo_story.json` (вымышленные сведения). GitHub web upload не применяет локальный `.gitignore`: при ручной загрузке проверяйте список файлов.

Не выводить API-ключи и полные личные истории в логи. Проверка доступа к истории выполняется на сервере до чтения/записи; идентификатор пользователя берётся из авторизованной сессии. Продукт нельзя считать готовым к публичному запуску без этой проверки.
