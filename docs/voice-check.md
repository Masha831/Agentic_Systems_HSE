# Голосовой ввод — часть Лизы

Основной сценарий: вопрос текстом → нажать микрофон → рассказать → остановить →
проверить/исправить расшифровку → сохранить → следующий вопрос текстом.
Кнопка озвучки вопроса скрыта по решению Лизы. Realtime не используется.

## Запуск

Из корня репозитория, Python 3.10+:

```sh
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
cp .env.example .env
.venv/bin/uvicorn backend.app.main:app --reload --port 8000
```

Нужны ffmpeg и ffprobe в PATH (на macOS: `brew install ffmpeg`).
Открыть http://localhost:8000. Микрофон работает на localhost или HTTPS;
по обычному HTTP на IP-адресе другого компьютера браузер может его не разрешить.

В `.env` локально заполнить `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`, поставить `MOCK=0`.
Секрет не присылать в чат и не коммитить. Для речи нужна роль `ai.speechkit-stt.user`,
для агентов — `ai.languageModels.user`. Пустой ключ автоматически включает MOCK.
В MOCK запись и сохранение настоящие, но текст распознавания и ответы агентов тестовые.

## Файлы

- `frontend/assets/voice.js`: MediaRecorder, уровни микрофона, освобождение устройства, IndexedDB.
- `frontend/assets/app.js`: запись, проверка текста, повтор, сохранение, воспроизведение оригинала, фото и создание истории.
- `frontend/assets/api.js`: сетевые вызовы, ключ повтора ответа.
- `backend/app/speech.py`: обработка аудио и вызов SpeechKit; запись делится на куски до 25 секунд.
- `backend/app/main.py`: загрузка/проверка файлов, STT и повтор распознавания.
- `backend/app/answer_delivery.py`: защита от повторного создания ответа.

## Проверка для демо

1. Создать историю, при желании загрузить фото JPG/PNG/WebP. Убедиться, что история остаётся после перезагрузки.
2. Разрешить микрофон. Записать 10–20 секунд: счётчик и индикатор уровня должны реагировать. Остановить.
3. Прослушать оригинал, исправить расшифровку. Перезагрузить: черновик и запись должны восстановиться.
4. Сохранить: ответ появляется в истории, следующий вопрос — на экране. Повторить пять раз.
5. В браузере запретить микрофон: показать понятную ошибку и возможность написать ответ/загрузить аудио.
6. При ошибке STT нажать повтор; исходное аудио должно остаться. При ошибке сохранения повтор использует прежний ключ.
7. Отменить запись; снова начать — микрофон должен работать.

Запись ограничена пятью минутами и 25 МБ, фото — 10 МБ. Локальный аудиочерновик
сохраняется после остановки, а не во время записи. Не закрывать вкладку во время
записи; браузер выводит предупреждение. При запрете IndexedDB показано предупреждение
о невозможности локального сохранения.

```sh
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
node --test tests/test_recorder.cjs
```

Автотесты не вызывают платные сервисы. Запись физическим микрофоном требует
ручной проверки перед демо. Загрузка тестового аудиофайла её не заменяет.

Существующий экран главы собирает текст только локально; вызов API редактора,
правки карточек и разрешение уточнений — отдельная интеграция команды;
этот PR не завершает их. Серверный путь «пять ответов → глава» проверяется автотестом.

## Проверено при подготовке PR

В браузере в MOCK: создание истории с загруженной фотографией; пять последовательных
ответов (четыре текстовых и один загруженный WAV); правка расшифровки; воспроизведение
аудио; восстановление текстового и аудиочерновика после reload; наличие всех пяти
сохранённых ответов после reload; переход в существующий экран главы. Ошибок JavaScript
в этой проверке не зафиксировано. Сохранение главы из UI на сервер не заявляется.

## Проверка реальных сервисов 21 октября 2026

С локальным ключом и MOCK=0 подтверждены: HTTP 200 от YandexGPT 5.1,
создание истории, сохранение текстового ответа, выделение людей и мест
архивистом и следующий вопрос по содержанию ответа. Запросы агентов в этой
проверке получили 200; перехода на заглушки в журнале не было.

Распознавание на живом SpeechKit пока не подтверждено. REST v1 не ответил
даже за 60 секунд на официальный речевой пример Яндекса; gRPC v3 завершился
по дедлайну; распознавание в самом AI Studio оставалось pending. Права
сервисного аккаунта и scope ключа для STT проверены, баланс положительный.
Точная причина задержки сервисом не сообщена; не считать её ошибкой ключа.
SDK для диагностической проверки v3 не является зависимостью приложения.

При таймауте приложение сохраняет исходный файл и сообщает, что SpeechKit
не ответил вовремя. Ответ можно написать текстом. После восстановления
SpeechKit повторить распознавание той же записи и приёмку с микрофоном.
