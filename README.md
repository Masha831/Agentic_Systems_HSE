# Помню — семейная история через голосовое интервью

Учебный проект четырёх студентов по агентам и вайбкодингу. Человек рассказывает воспоминания, интервьюер помогает уточнить детали, архивист связывает людей и события с источниками, редактор собирает главу с фотографиями и оригинальным голосом.

**Статус: организационный каркас. Рабочий сервер, агенты, база и интеграция с Яндексом ещё не реализованы.** Файлы README в папках объясняют, какие файлы создать и что в них писать. Это распределение ответственности за разработку, а не утверждение об авторстве уже написанного кода.

## Кто куда пишет

| Участник | Папки | Ответственность | Первый результат |
|---|---|---|---|
| **Лиза** | [`backend/voice`](backend/voice/README.md), [`backend/media`](backend/media/README.md), [`frontend/assets/voice`](frontend/assets/voice/README.md) | Yandex Realtime, микрофон, звук, запись, фотографии, ошибки и восстановление | Голосовой разговор в браузере; аудио и текст сохраняются |
| **Маша** | [`backend/interviewer`](backend/interviewer/README.md) | Инструкции и логика интервью, контекст, инструменты, продолжение беседы | Агент задаёт уместные вопросы, учитывает память и пропущенные темы |
| **Максим / werserk** | [`backend/archive`](backend/archive/README.md), [`backend/shared`](backend/shared/README.md) | Архивист, база, люди, события, факты, источники и поиск памяти | Из нового ответа появляются сведения с проверяемыми источниками |
| **Дарья** | [`backend/editor`](backend/editor/README.md), [`frontend/assets/archive`](frontend/assets/archive/README.md) | Сборка главы, просмотр истории, карточки людей и событий | Читаемая глава с переходами к людям и исходным записям |

Все четверо пишут код и проверяют интеграцию. Сервер — **Python**. Небольшой браузерный JavaScript обслуживает микрофон и существующий HTML-интерфейс. UI Маши используем как основу; дизайн-систему заново не делаем. Сам UI ещё не импортирован в этот каркас.

## Структура

```text
backend/
  interviewer/   # Маша: поведение голосового интервьюера
  voice/         # Лиза: связь браузера с Yandex Realtime
  media/         # Лиза: аудио и фотографии
  archive/       # Максим: хранилище и агент-архивист
  editor/        # Дарья: агент-редактор
  shared/        # Общие модели; координирует Максим
frontend/
  assets/voice/  # Лиза: микрофон, звук, экран интервью
  assets/archive/# Дарья: история, карточки, источники
  README.md      # Правила подключения существующего UI
examples/
  demo_story.json # Только вымышленные данные для общей проверки
tests/
  README.md       # Проверки по модулям и общий сценарий
docs/
  CONTRACTS.md    # Как модули вызывают друг друга
  MVP.md          # Сценарий и условия готовности
CONTRIBUTING.md   # Ветки, PR, запуск разработки
.env.example     # Пустые настройки, никаких ключей
```

## С чего начать каждому

1. Прочитать README своей папки и [контракты](docs/CONTRACTS.md).
2. Создать свою ветку от `main` по [инструкции](CONTRIBUTING.md).
3. Начать с одного минимального результата из таблицы выше. Пока соседний модуль не готов, использовать явно обозначенный mock на вымышленном примере.
4. В PR указать, что работает реально, что остаётся заглушкой, как проверить и какой интерфейс изменился.
5. Собрать [общий сценарий MVP](docs/MVP.md) на новом рассказе.

## Порядок интеграции

- Лиза и Маша: голосовая сессия с промптом и без инструментов.
- Лиза и Максим: надёжное сохранение реплик и аудио, исправление расшифровки.
- Маша и Максим: поиск памяти и продолжение истории во второй сессии.
- Дарья и Максим: глава, люди, события и ссылки на первоисточники.
- Все: полный проход с ошибкой связи, отказом от темы и повторным открытием истории.

Рекомендуемое начальное устройство — один Python backend с модулями. Не нужно поднимать четыре отдельных сервера. `backend/main.py` собирает маршруты, первая интеграция — Лиза с владельцами модулей. Веб-фреймворк и зависимости пока не зафиксированы: добавляем их первым рабочим PR вместе с командой запуска.

## О голосовом режиме

Текущий план — Yandex Realtime. Его модель ведёт разговор по инструкциям Маши; Лиза подключает транспорт и аудио. Архивист и редактор выполняют отдельные задачи. Долговременная память хранится в вашем приложении, не только в голосовой сессии. Модель не должна ждать полной обработки архивистом после каждой фразы: исходная реплика сохраняется сразу, обработка идёт отдельно, состояние готовности видно приложению.

[Realtime: официальная документация](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/agents/realtime).
